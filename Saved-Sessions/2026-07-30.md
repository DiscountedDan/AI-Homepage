## Architecture & Key Decisions
- `ai_todos` is a flat array (`{ id, text, completed }`), no seed data, `Date.now()` ids — same pattern as `ai_recipes`.
- Delete has no confirmation modal (unlike Resource/Recipe deletes) — intentionally lighter-weight since re-adding a task is cheap.
- No in-place editing; delete-and-re-add is the correction flow.
- Completed tasks sink into their own group below open tasks (divider only, no heading); open tasks prepend newest-first.
- **Correction mid-session:** the scroll container must use a fixed `height`, not `max-height`. `max-height` only caps growth once content reaches it — the box still visibly grows with each added task up to that cap. Worse, because the four Home widgets sit in a CSS grid with default stretch-alignment, one card's growth stretches *all* sibling cards in that row to match. Fixed by changing `.todo-scroll` to `height: 210px`, so the box is constant from 0 tasks onward.
- No browser automation was available this session (chromium-cli, jsdom, and puppeteer are all absent from the environment; the user declined the Claude-in-Chrome extension). Logic was verified instead by extracting the real functions from `index.html` and running them against a minimal hand-written DOM/localStorage shim in Node — this caught logic bugs but not the visual/layout bug, which the user found by eye.
